# Журнал изменений

## Не выпущено — `compat/0.2.0` (линия DSH 0.2.0)

### Изменено

- `peerDependencies` и `engines.dsh` переориентированы на линию DSH 0.2.0:
  `>=0.2.0-rc.1 <0.2.1-0` (package.json + dsh.plugin.json). Только метаданные:
  каждая поверхность, читаемая этим плагином (снимок `sessions.list`,
  `WorkspaceSnapshot`/`WorkspaceView`, `uiWorkspace.connectWorkspace`),
  сравнивалась между декларациями 0.1.7-rc.2 и 0.2.0-rc.1 — только добавленные
  поля, ничего не удалено.
- Документация по установке указывает на
  `github:drscrewdriver/dsh-arrowkey-nav#compat/0.2.0`; пакет в реестре выходит
  как `0.4.0` под dist-tag `dsh-0.2.0`.

## Не выпущено — `compat/0.1.7` (линия DSH 0.1.7)

### Изменено

- `peerDependencies` и `engines.dsh` переориентированы на линию DSH 0.1.7:
  `>=0.1.7-rc.1 <0.1.8-0` (package.json + dsh.plugin.json). Только метаданные:
  читающий набор детекторов 0.1.7 (D1–D11) не даёт ни одного срабатывания, и
  этот плагин не импортирует модули `@deepseek-ai/*` ни при сборке, ни в тестах.
- Документация по установке указывает на
  `github:drscrewdriver/dsh-arrowkey-nav#compat/0.1.7`; пакет в реестре выходит
  как `0.3.3` под dist-tag `dsh-0.1.7`.

### Добавлено

- Плоская конфигурация ESLint (проверяемая типами база для src, рекомендуемая
  база для tests) и npm-скрипт `lint`; `npm run lint` проходит чисто.

## Не выпущено — `compat/0.1.5-rc` (линия DSH 0.1.5)

### Изменено

- `engines.dsh` сужен до `>=0.1.5-alpha.1 <0.2.0-0` — диапазон, который эта
  ветка реально реализует. `dsh.plugin.json` теперь несёт тот же диапазон вместо
  устаревшего `>=0.1.2-rc.1`, унаследованного от `master`.
- Документация по установке указывает на
  `github:drscrewdriver/dsh-arrowkey-nav#compat/0.1.5-rc`; пакет в реестре
  (`dsh-arrowkey-nav@0.1.1`) остаётся линией ~0.1.2 ветки `master`, а
  формулировки README о поддерживаемом диапазоне согласованы с манифестом.

### Добавлено

- Аксессор консольных свидетельств только для чтения
  `globalThis.__dshArrowkeyNav.snapshot()` (`diagnose-console.js`), который
  сообщает формы снимков `sessions` / `workspaces`, реально загруженные
  страницей, чтобы адаптацию 0.1.5 можно было проверить на живом хосте.

## 0.1.1

### Исправлено

- `types` и `exports["."].types` указывали на `lib/types/index.d.ts`, который
  сборка никогда не создаёт — файла не было ни на диске, ни в опубликованном
  tarball 0.1.0, поэтому потребители TypeScript не получали деклараций. Теперь
  оба указывают на `lib/index.d.ts`, который создаётся и поставляется.
- `engines` отсутствовал полностью, поэтому ни версия Node, ни версия DSH не
  были ограничены. Теперь объявлены обе.
- `lib/` был в gitignore, и ни один хук его не собирал, поэтому публикация из
  чистого клона поставила бы tarball вообще без скомпилированных файлов. Добавлен
  хук `prepublishOnly`.

### Добавлено

- `dsh.plugin.json`, манифест показа `screenshots.json`, а также
  `repository` / `homepage` / `keywords`.
- README и журналы изменений на японском и корейском, а также руководство по
  установке на английском, упрощённом китайском, японском и корейском.

## 0.1.0

Первый выпуск: навигация клавишами-стрелками для веб-GUI DSH.

### Добавлено

- `↑` / `↓` переключают на предыдущую / следующую сессию в текущем рабочем
  пространстве, зацикливаясь на границах и никогда не заходя в соседнее
  пространство.
- `←` / `→` переключают рабочие пространства по всем.
- После переключения целевая строка прокручивается в область видимости, а фокус
  возвращается в поле ввода, если нажатие началось там, так что печатать можно
  продолжать сразу.
- Идентичность сессии читается из двух клиентских контроллеров (`ctx.sessions`,
  `ctx.workspaces`), никогда из DOM: строки не несут ни `data-*`, ни `id`,
  поэтому у строки нельзя спросить, какая она сессия.
- «Следующая» следует порядку, который боковая панель рисует сейчас,
  согласованному с составом участников контроллера; при несмонтированной панели
  (свёрнутой в узкую полосу) возврат к порядку контроллера, а неоднозначная или
  несовпадающая секция возвращает управление, а не угадывает.
- Стрелки отдаются тому, кто уже владеет событием: любой модификатор, композиция
  IME, событие, уже обработанное выше по стеку, или фокус внутри диалога, меню
  или другого редактируемого поля.
- Пустое поле ввода отдаёт свои стрелки; поле ввода с черновиком оставляет их
  каретке, так что редактирование промпта никогда не перехватывается.
- Слушатель регистрируется на фазе захвата, но вызывает `preventDefault()`
  только когда действительно выполняет навигацию.
- Браузерная половина не содержит ни компонентов React, ни CSS, ни запросов
  платформенных модулей, а у пакета нет зависимостей времени выполнения.

### Известные ограничения

- Свёрнутая группа рабочих пространств не прокручивается: её строки не
  смонтированы, а dsh не предоставляет публичного способа развернуть группу.
  Переключение всё же происходит. Рабочее пространство с текущей сессией dsh сам
  держит развёрнутым, поэтому `↑`/`↓` не затронуты.
- Боковая панель, свёрнутая в узкую полосу, не прокручивается по той же причине.
- Режим «в одном списке» не имеет секций по рабочим пространствам, но `←`/`→`
  всё равно идут по порядку пространств контроллера, поэтому список может
  казаться перескакивающим между секциями.
- Прокрутка выполняется по мере возможностей — любая ошибка поиска проглатывается,
  потому что выделение уже переместилось, а отсутствующая строка никогда не
  должна обернуться неверной.
- Закреплено на dsh 0.1.2-rc.1: поля снимков `sessions` и `workspaces` ещё не
  стабилизированы. Если обновление dsh их изменит, пересмотреть нужно только
  `src/client/navigate.ts` и `src/client/apply.ts`; исчезнувший сервис оставит
  плагин в ожидании, а не уронит страницу.
